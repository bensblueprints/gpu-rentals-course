3 · The 60-second listing check

  • VRAM ≥ model + headroom (weights + KV cache + engine + ~4GB margin).
  • Reliability ≥ 98% — below that, expect the host to die mid-job.
  • Network listed in Mbps — no number shown = assume it's bad. (Same platform: 60 vs 6,783 Mbps.)
  • Region matches your data — cross-continent transfers run at ~1 MB/s.
  • RAM ≥ 2× VRAM, disk ≥ dataset + outputs.
  • Fleet check — would N cheaper cards beat this one for this job?

6 · Operations in four lines

  • flock -n — one master, ever. No duplicate workers.
  • Skip finished work — every job resumable; rerunning is always safe.
  • Watchdog via cron every 15 min — restart what dies.
  • rsync out every 60s — hosts die; you lose seconds, not hours.
Rent the hardware. Own the models, the pipeline, and the metadata — never the host.
